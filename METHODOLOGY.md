# A Controlled Study of Stream Prefetching for Transformer KV-Cache Memory Hierarchies

**Scope.** This is a **simulation and analytical-modeling study**, not a silicon
result. It makes no validated claims about TOPS, watts, die area, or model
perplexity (see [`LIMITATIONS.md`](LIMITATIONS.md)). Its contribution is a
correct, validated, reproducible characterization of hardware stream
prefetching for the memory-access patterns that arise in transformer
key/value-cache traffic, including a multi-stream prefetcher that fixes a
concrete failure of the single-stream design.

All numbers below are emitted by scripts in this repository and regenerated by
`bash scripts/reproduce_paper.sh`.

## 1. Motivation

Autoregressive LLM inference is memory-bound: each generated token re-reads the
KV cache for every layer. A common architectural response is a large on-chip
cache plus a prefetcher. A credible evaluation of such a prefetcher requires (a)
a **correct** cycle model and (b) a **demand-only control** to attribute any
benefit to the prefetcher rather than to cache capacity. The prior version of
this project had neither: its simulator double-counted demand misses as cache
hits, and it had no way to disable prefetching, so its headline "99.99% hit
rate from the prefetcher" was an artifact (the prefetcher issues zero requests
on the shipped KV trace; the hits come from the working set fitting in cache).

## 2. Methodology

### 2.1 Simulator

`src/simulator/janus_sim.py` models a two-tier hierarchy: a T1 SRAM cache
(LRU, banked, 1-cycle hit) backed by a T2 store (multi-bank, `t2_latency`-cycle
fill). The core is in-order with a single outstanding demand miss; the prefetch
engine issues opportunistically, breadth-first over look-ahead distance and
throttled by an issue width. **Each trace access is retired exactly once** —
the correctness property the previous loop violated.

Prefetch policy is a first-class knob (`prefetch_mode`):
`none` (demand-only control), `next_line`, `stream` (single unit-stride FSM),
and `multi_stream` (an LRU table of unit-stride detectors, each confirmed after
two consecutive lines).

### 2.2 Validation

Before trusting any result we pin the cycle model to closed-form expectations
(`experiments/validate_simulator.py`, enforced by
`tests/test_analytical_validation.py`): a cold demand miss costs exactly
`t1+t2` cycles; a warm hit costs `t1`; cold sequential and LRU-thrash workloads
yield 0% hits; an ideal single stream exceeds 99%; and `multi_stream` recovers
8 interleaved streams. All checks pass.

### 2.3 Workloads

To attribute hits to prefetching rather than reuse, workloads are
**single-pass** (each unique line demanded once), so the demand-only hit rate
is 0% by construction. We use `sequential`, `strided-2`, `streaming-8` (8
interleaved unit-stride streams, modeling per-layer KV reads), `mixed-0.7`
(70% sequential / 30% random), and a sparse `random` negative control.
Stochastic workloads are run over 15 seeds with 95% bootstrap confidence
intervals and effect sizes.

## 3. Results

### 3.1 Prefetcher ablation (`experiments/prefetch_ablation.py`)

| workload | none | next_line | stream | multi_stream | notes |
|---|---|---|---|---|---|
| sequential | 0.0% | 99.99% (1.0×) | 99.98% | 99.98% | ideal case, 1× bandwidth |
| strided-2 | 0.0% | 99.99% (**2.0×**) | 0.0% | 0.0% | unit-stride FSMs stay quiet |
| streaming-8 | 0.0% | 99.93% | **0.0%** | **99.87%** | single FSM fails; multi recovers |
| mixed-0.7 | 3.9% | 79.7% (3.48×, p99 22) | 72.2% (**0.69×**, p99 11) | 72.2% (0.69×) | stream far more BW-efficient |
| random | 0.1% | 1.7% (**15.7×**, p99 37) | 0.1% | 0.1% | prefetch cannot help; next-line harmful |

(Bandwidth overhead = prefetch fetches per demand read; hit-rate CIs are ≤0.1%
wide and omitted for space.) On `mixed`, stream vs demand-only is significant
(Mann–Whitney p < 1e-4, large effect); on `random` it is not (p = 1.0, d = 0),
exactly as it should be.

**Takeaway.** `multi_stream` attains `next_line`'s coverage on streaming
workloads while matching the demand-only baseline's efficiency on
non-streaming access — it is the only policy that is both effective and
bandwidth-safe across the suite.

### 3.2 Design-space sensitivity (`experiments/prefetch_sensitivity.py`)

Two clean laws:
- **Stream-table size:** hit rate is ~0% until the table holds ≥ the number of
  concurrent streams, then jumps to ~99% (step at 4/8/12 entries for 4/8/12
  streams). A single-stream detector is a table of size 1 and thus fails for any
  concurrency > 1.
- **Look-ahead depth:** hit rate saturates once depth ≥ the T2 fill latency
  (knee at depth 3 for `t2_latency_cycles = 3`).

### 3.3 Technology-selection robustness (`experiments/power_robustness.py`)

The absolute power constants are uncalibrated and are **not** cited as results.
Under ±50% log-uniform uncertainty on every constant, eDRAM remains lower-power
than HD-SRAM for the 224 MB leakage-dominated cache with probability ≈ 1.0
(median 15.6× ratio, 95% MC interval [6.7×, 36.2×]). The **ordering** is
trustworthy even though the absolute watts are not.

## 4. Threats to Validity

- **Absolute power/area/latency values are uncalibrated** (no CACTI/DRAMPower/
  PDK). Only relative orderings and cycle-level ratios are claimed.
- **The cycle model is validated analytically, not against a reference
  simulator** (gem5/Ramulator). Bank timing is approximate.
- **Workloads are synthetic.** The shipped LLM KV trace in particular has ~0%
  line-level spatial locality, so it does not exercise the prefetcher; realistic
  KV layouts would.
- **`multi_stream` handles only unit strides;** non-unit strides (e.g.
  `strided-2`) still require next-line-style coverage.


## 6. Conclusion & Future Work

A corrected, validated simulator plus a proper demand-only control turns a set
of unsubstantiated claims into a small but honest result: stream prefetching for
KV-cache-like traffic helps only in specific, characterizable regimes, and a
compact multi-stream table fixes the single-stream design's failure on
interleaved streams without the bandwidth cost of blind next-line prefetching.
Genuine publishability still requires calibrated power/area models, a
reference-simulator cross-check, stride-aware multi-stream detection, and traces
captured from a real inference engine — the roadmap in `LIMITATIONS.md` §7.
